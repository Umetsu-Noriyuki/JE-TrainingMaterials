# 第4章：ER図の記法とカーディナリティ

ER図にはいくつかの記法が存在しますが、現在のシステム開発において最も一般的に使用されているのが**IE（Information Engineering）記法**、通称**「鳥の足記法 (Crow's Foot Notation)」**です。

## 1. 線の両端にある記号（カーディナリティとオプショナリティ）

テーブル間を結ぶ線の両端には、「相手のレコードがいくつ存在し得るか」を示す記号が描かれます。これを正しく読み取ることで、テーブル結合（JOIN）時に「データが何件に増えるか」「NULLになる可能性があるか」を予測できます。

記号は**「オプショナリティ（必須か任意か）」**と**「カーディナリティ（1か多か）」**の組み合わせで構成されます。線の端から内側に向かって読みます。

### 代表的な記号のパターン

1. **`－| |`（1のみ / 必須）**
   - 縦線が2本。対象レコードが「必ず1件だけ」存在することを示します。
   - 例：注文明細から見た「注文」。（明細は必ずどこか1つの注文に属する）

2. **`－O |`（0または1 / 任意）**
   - 丸と縦線。対象レコードが存在しない（0件）場合もあるが、最大でも1件であることを示します。
   - 例：社員から見た「退職情報」。（退職していない社員にはデータがない）

3. **`－| ＜`（1以上 / 必須の多）**
   - 縦線と鳥の足（枝分かれ）。対象レコードが「1件以上（複数可）」必ず存在することを示します。
   - 例：注文から見た「注文明細」。（空の注文は存在せず、必ず1つ以上の明細がある）

4. **`－O ＜`（0以上 / 任意の多）**
   - 丸と鳥の足。対象レコードが存在しない場合もあるし、複数存在する場合もあることを示します。
   - 例：顧客から見た「注文」。（まだ一度も注文していない顧客もいるし、何度も注文している顧客もいる）

## 2. 実務におけるER図の読み方とSQLへの影響

ER図を読む際、保守・運用エンジニアは以下のポイントから「SQLを実行した時の挙動」をイメージします。

### ① JOINによる件数増幅（Cartesian Productの回避）
鳥の足（＜）の方向に向かってJOINを行うと、取得される結果セットの行数は**増えます**。
「顧客」と「注文」をJOINした場合、顧客1人に対して注文が3件あれば、結果は3行になります。意図せず集計値が倍増してしまうミス（ファン・トラップ）を防ぐため、1対多の方向を意識することが重要です。

### ② OUTER JOINの必要性
丸（O）の記号がある方向へJOINする場合、紐づくレコードが存在しない（0件の）可能性があります。
このとき通常の `INNER JOIN` を使うと、元となるレコードごと結果から消滅してしまいます。データが欠落しないよう `LEFT OUTER JOIN` などを適切に選択する判断基準になります。

## 3. 本章のまとめ
- IE記法（鳥の足記法）では、線の端の記号で「0、1、多」の条件を読み取る。
- 親（1）から子（多）へ結合すると行数が増えるため、集計関数（SUMなど）の扱いに注意が必要。
- 任意（O）の関係を持つテーブルを結合する際は、INNER JOINによるデータ欠落リスクを意識する。
