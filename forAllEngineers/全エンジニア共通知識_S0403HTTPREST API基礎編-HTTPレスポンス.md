# 3. HTTPレスポンス

## 3.1 HTTPレスポンスとは

**HTTPレスポンス**とは、サーバーからクライアントへ返される応答のことです。

HTTP通信では、クライアントがHTTPリクエストを送信すると、サーバーはそのリクエストに対してHTTPレスポンスを返します。

```text
クライアント
    │
    │ HTTPリクエスト
    ▼
サーバー
    │
    │ HTTPレスポンス
    ▼
クライアント
```

例えば、APIからユーザー情報を取得する場合、

```text
クライアント
    │
    │ GET /users/1
    ▼
サーバー
    │
    │ ユーザー情報
    ▼
クライアント
```

のような通信が行われます。

HTTPレスポンスには、主に以下のような情報が含まれます。

* 処理が成功したかどうか
* レスポンスに関する追加情報
* サーバーから返すデータ

---

## 3.2 HTTPレスポンスの構成

HTTPレスポンスは、主に以下の要素で構成されます。

```text
ステータスライン
ヘッダー
ボディ
```

例えば、以下のようなHTTPレスポンスがあります。

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 1,
    "name": "山田太郎",
    "age": 25
}
```

この例では、それぞれ以下の情報を表しています。

| 要素       | 内容                               |
| -------- | -------------------------------- |
| ステータスライン | `HTTP/1.1 200 OK`                |
| ヘッダー     | `Content-Type: application/json` |
| ボディ      | ユーザー情報のJSON                      |

---

## 3.3 ステータスコード

**ステータスコード**は、サーバーがHTTPリクエストを処理した結果を表す3桁の数字です。

例えば、

```text
200
```

は、リクエストが正常に処理されたことを表します。

ステータスコードは、先頭の数字によって大まかな意味が分かれています。

| 分類    | 意味          |
| ----- | ----------- |
| `1xx` | 情報          |
| `2xx` | 成功          |
| `3xx` | リダイレクト      |
| `4xx` | クライアント側のエラー |
| `5xx` | サーバー側のエラー   |

APIを扱うときは、特に`2xx`、`4xx`、`5xx`をよく使用します。

---

## 3.4 2xx 成功

`2xx`は、リクエストが正常に処理されたことを表します。

### 200 OK

`200 OK`は、リクエストが正常に処理されたことを表します。

例えば、ユーザー情報を取得した場合、

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 1,
    "name": "山田太郎"
}
```

のようなレスポンスが返されます。

---

### 201 Created

`201 Created`は、リクエストによって新しいデータが作成されたことを表します。

例えば、APIを使用して新しいユーザーを登録した場合に使用されます。

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
    "id": 10,
    "name": "佐藤花子"
}
```

---

### 204 No Content

`204 No Content`は、リクエストが正常に処理されたものの、レスポンスボディに返すデータがないことを表します。

例えば、データを削除した場合などに使用されることがあります。

```http
HTTP/1.1 204 No Content
```

---

## 3.5 4xx クライアント側のエラー

`4xx`は、クライアントから送信したリクエストに問題がある場合などに使用されます。

### 400 Bad Request

`400 Bad Request`は、リクエストの内容に問題があることを表します。

例えば、APIが数値を要求しているのに、文字列を送信した場合などが考えられます。

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
    "error": "Invalid request"
}
```

---

### 401 Unauthorized

`401 Unauthorized`は、認証が必要なAPIなどで、適切な認証情報が提供されていない場合などに使用されます。

```http
HTTP/1.1 401 Unauthorized
```

例えば、ログインが必要なAPIに、認証情報を付けずにアクセスした場合などです。

---

### 403 Forbidden

`403 Forbidden`は、リクエストを理解したものの、アクセスする権限がない場合などに使用されます。

```http
HTTP/1.1 403 Forbidden
```

例えば、ログインはできているものの、そのユーザーにはアクセスする権限がない場合などです。

---

### 404 Not Found

`404 Not Found`は、指定したURLやリソースが存在しない場合などに使用されます。

```http
HTTP/1.1 404 Not Found
```

例えば、

```http
GET /users/9999
```

とリクエストしたものの、IDが`9999`のユーザーが存在しない場合などです。

---

## 3.6 5xx サーバー側のエラー

`5xx`は、サーバー側で問題が発生した場合に使用されます。

### 500 Internal Server Error

`500 Internal Server Error`は、サーバー内部で予期しないエラーが発生したことを表します。

```http
HTTP/1.1 500 Internal Server Error
```

この場合、リクエストを送ったクライアント側ではなく、サーバー側で問題が発生している可能性があります。

---

### 503 Service Unavailable

`503 Service Unavailable`は、サーバーが一時的にリクエストを処理できない場合などに使用されます。

```http
HTTP/1.1 503 Service Unavailable
```

例えば、サーバーがメンテナンス中の場合などに使用されることがあります。

---

## 3.7 レスポンスヘッダー

**レスポンスヘッダー**は、サーバーから返されるHTTPレスポンスに関する追加情報です。

例えば、以下のようなヘッダーがあります。

```http
Content-Type: application/json
```

`Content-Type`は、レスポンスボディに含まれているデータの形式を表します。

APIでは、JSON形式のデータを返す場合に、

```http
Content-Type: application/json
```

と指定されることがあります。

その他にも、キャッシュに関する情報や、サーバーに関する情報など、さまざまな情報がレスポンスヘッダーに含まれることがあります。

---

## 3.8 レスポンスボディ

**レスポンスボディ**は、サーバーからクライアントへ返されるデータを格納する部分です。

APIでは、JSON形式のデータをレスポンスボディとして返すことがよくあります。

例えば、ユーザー情報を取得した場合、

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 1,
    "name": "山田太郎",
    "age": 25
}
```

以下の部分がレスポンスボディです。

```json
{
    "id": 1,
    "name": "山田太郎",
    "age": 25
}
```

このデータをクライアント側で受け取り、画面に表示したり、別の処理に利用したりします。

JSONについては、5章「JSONとAPI通信」で詳しく説明します。

---

## 3.9 HTTPリクエストとレスポンス

HTTP通信では、リクエストとレスポンスがセットで使用されます。

例えば、ユーザー情報を取得する場合は以下のような流れになります。

### ① クライアントからリクエストを送信

```http
GET /users/1 HTTP/1.1
Host: example.com
```

### ② サーバーが処理する

サーバーはリクエストを受け取り、指定されたユーザーの情報を検索します。

### ③ サーバーからレスポンスを返す

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 1,
    "name": "山田太郎"
}
```

このように、

```text
リクエスト
    ↓
サーバーで処理
    ↓
レスポンス
```

という流れでHTTP通信が行われます。

---

## 3.10 APIでよく見るステータスコード

APIを利用するときは、レスポンスのステータスコードを確認することが重要です。

特によく使用されるものをまとめると、以下のようになります。

| ステータスコード                    | 意味           | 例              |
| --------------------------- | ------------ | -------------- |
| `200 OK`                    | 正常に処理された     | データ取得          |
| `201 Created`               | データが作成された    | データ登録          |
| `204 No Content`            | 正常だが返すデータがない | データ削除          |
| `400 Bad Request`           | リクエストに問題がある  | パラメータ不正        |
| `401 Unauthorized`          | 認証が必要        | 認証情報がない        |
| `403 Forbidden`             | 権限がない        | アクセス権限不足       |
| `404 Not Found`             | 対象が存在しない     | 指定したIDが存在しない   |
| `500 Internal Server Error` | サーバー内部でエラー   | サーバー側の予期しないエラー |
| `503 Service Unavailable`   | 一時的に利用できない   | メンテナンス中など      |

APIの動作確認をするときは、レスポンスボディだけではなく、**ステータスコードも確認することが重要です。**

---

## 3.11 まとめ

* HTTPレスポンスは、サーバーからクライアントへ返される応答
* HTTPレスポンスには、ステータスコード、ヘッダー、ボディなどが含まれる
* ステータスコードによって処理結果を確認できる
* `2xx`は成功を表す
* `4xx`はクライアント側のエラーを表す
* `5xx`はサーバー側のエラーを表す
* レスポンスヘッダーには、レスポンスに関する追加情報が含まれる
* レスポンスボディには、サーバーから返されるデータが含まれる
* APIではJSON形式のレスポンスボディがよく使用される
* APIを利用するときは、ステータスコードとレスポンスボディの両方を確認する

HTTP通信では、

```text
クライアント
    │
    │ HTTPリクエスト
    ▼
サーバー
    │
    │ HTTPレスポンス
    ▼
クライアント
```

というやり取りが基本になります。

次の章では、HTTPを利用してデータの取得や登録などを行う**APIとREST API**について学びます。
