### 7.1 API仕様書とは

#### ① API仕様書とは？

API仕様書とは、APIの利用方法やルールをまとめたドキュメントのこと。

APIを利用する側が、どのようなリクエストを送ればよいのか、どのようなレスポンスが返ってくるのかを確認できる。

#### ② API仕様書に記載される内容

API仕様書には、主に次のような情報が記載されている。

- **エンドポイント**：APIにアクセスするURL
- **HTTPメソッド**：GET、POST、PUT、PATCH、DELETEなど
- **リクエストパラメータ**：APIに送信するデータや条件
- **リクエストボディ**：POSTやPUTなどで送信するデータ
- **レスポンス**：APIから返されるデータ
- **ステータスコード**：リクエストの処理結果を表す番号
- **認証方法**：APIを利用するために必要な認証方式

#### ③ API仕様書を確認する理由

API仕様書を確認することで、APIの正しい利用方法を理解できる。

例えば、次のようなことを事前に確認できる。

- どのURLにアクセスすればよいか
- どのHTTPメソッドを使用するか
- どのデータを送信する必要があるか
- どのような形式でデータが返ってくるか
- エラーが発生した場合に何が返ってくるか

仕様書を確認せずにAPIを利用すると、誤ったリクエストを送信してエラーになる可能性がある。

#### ④ API仕様書の活用

API仕様書は、APIを開発する側と利用する側の共通ルールとして使われる。

開発者同士で仕様を共有することで、認識の違いを減らし、スムーズに開発を進められる。


### 7.2 Swagger / OpenAPI

#### ① OpenAPIとは？

OpenAPIとは、REST APIの仕様を記述するための標準的なフォーマットのこと。

APIのエンドポイントやHTTPメソッド、リクエスト、レスポンス、認証方法などを共通の形式で定義できる。

OpenAPIを利用することで、APIの仕様を機械的に読み取れる形式で管理できる。

#### ② Swaggerとは？

Swaggerとは、OpenAPIに関連するツール群のこと。

OpenAPIの仕様を利用して、API仕様書の表示やAPIの動作確認などを行える。

代表的なツールにSwagger UIがある。

#### ③ Swagger UIとは？

Swagger UIとは、OpenAPIで記述されたAPI仕様を、ブラウザ上で見やすく表示するツールのこと。

主な機能：

- APIのエンドポイントやHTTPメソッドを確認できる
- リクエストパラメータやレスポンスの形式を確認できる
- ブラウザ上からAPIリクエストを実行できる
- APIのレスポンスやステータスコードを確認できる

#### ④ OpenAPIとSwaggerの違い

| 用語 | 役割 |
|---|---|
| OpenAPI | API仕様を記述するための標準フォーマット |
| Swagger | OpenAPIを利用するためのツール群 |
| Swagger UI | API仕様をブラウザ上に表示・操作するツール |

OpenAPIは「仕様を記述するルール」、Swaggerは「その仕様を扱うためのツール」と覚えると分かりやすい。

#### ⑤ OpenAPIを利用するメリット

- API仕様を統一した形式で管理できる
- 開発者同士でAPIの仕様を共有しやすい
- Swagger UIなどで仕様を確認しやすい
- APIクライアントやテストコードの自動生成に活用できる


### 7.3 Postmanとは

#### ① Postmanとは？

Postmanとは、APIにリクエストを送信し、レスポンスを確認するためのツールのこと。

プログラムを書かなくても、画面上からAPI通信を実行できる。

APIの開発やテスト、動作確認などで利用される。

#### ② Postmanでできること

Postmanでは、主に次のような操作ができる。

- **HTTPメソッドの指定**：GET、POST、PUT、PATCH、DELETEなどを選択できる
- **URLの指定**：アクセスするAPIのエンドポイントを入力できる
- **ヘッダーの設定**：認証情報やContent-Typeなどを指定できる
- **リクエストボディの設定**：JSONなどのデータを送信できる
- **レスポンスの確認**：返されたデータやステータスコードを確認できる

#### ③ Postmanを利用するメリット

- プログラムを書かずにAPI通信を確認できる
- APIの動作確認やテストを簡単に行える
- リクエストの内容を保存して、繰り返し利用できる
- 複数のAPIリクエストをまとめて管理できる

#### ④ Swagger UIとの違い

| 項目 | Swagger UI | Postman |
|---|---|---|
| 主な目的 | API仕様の確認・操作 | APIリクエストの実行・テスト |
| 仕様の表示 | OpenAPI仕様を表示できる | API情報を管理できる |
| リクエスト実行 | 可能 | 可能 |
| 主な用途 | API仕様の確認 | APIの動作確認やテスト |

どちらもAPIリクエストを実行できるが、Swagger UIは仕様の確認、Postmanはリクエストの作成やテストに強みがある。

#### ⑤ Postman利用時の注意点

APIを実行するときは、認証情報やAPIキーなどの秘密情報を適切に管理する必要がある。

また、本番環境のAPIに対してテストを行う場合は、実際のデータを変更・削除してしまわないよう注意する。


### 7.4 APIリクエストを実行する

#### ① APIリクエストとは？

APIリクエストとは、クライアントからサーバーに対して処理やデータを要求すること。

例えば、ユーザー情報を取得したり、新しいデータを登録したりするときにAPIリクエストを送信する。

#### ② APIリクエストの基本的な構成

APIリクエストには、主に次の情報が含まれる。

- **HTTPメソッド**：GET、POST、PUT、PATCH、DELETEなど
- **URL（エンドポイント）**：アクセスするAPIの場所
- **ヘッダー**：認証情報やデータ形式などの追加情報
- **リクエストボディ**：サーバーに送信するデータ

例えば、次のようなリクエストがある。

```http
POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer <token>

{
  "name": "Taro",
  "age": 20
}
```

このリクエストでは、ユーザー情報をJSON形式で送信している。

#### ③ APIリクエストを実行する流れ
APIリクエストは、一般的に次の流れで実行する。
1. API仕様書でエンドポイントやHTTPメソッドを確認する
2. リクエスト先のURLを指定する
3. HTTPメソッドを選択する
4. 必要なヘッダーを設定する
5. 必要に応じてリクエストボディを設定する
6. リクエストを送信する
7. サーバーからのレスポンスを確認する

#### ④ リクエスト時の注意点
APIリクエストを送信するときは、次の点に注意する。
- HTTPメソッドを正しく指定する：取得・登録・更新・削除など、目的に合ったメソッドを使用する
- ヘッダーを正しく設定する：認証が必要な場合はトークンなどを指定する
- データ形式を確認する：JSONを送る場合はContent-Typeを適切に設定する
- 必須項目を確認する：API仕様書に記載された必須パラメータを送信する
- 秘密情報を適切に扱う：パスワードやAPIキーなどを不用意に公開しない
正しいリクエストを送信するためには、API仕様書に従うことが重要。

### 7.5 APIレスポンスを確認する

#### ① APIレスポンスとは？

APIレスポンスとは、クライアントから送信されたリクエストに対して、サーバーが返す処理結果のこと。

レスポンスには、取得したデータや処理結果、エラー情報などが含まれる。

#### ② APIレスポンスの基本的な構成

APIレスポンスには、主に次の情報が含まれる。

- **ステータスコード**：リクエストの処理結果を表す番号
- **レスポンスヘッダー**：データ形式やキャッシュなどの追加情報
- **レスポンスボディ**：サーバーから返されるデータやメッセージ

例えば、次のようなレスポンスがある。

```
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "name": "Taro",
  "age": 20
}

```

この例では、200 OKが返され、ユーザー情報がJSON形式で取得できている。

#### ③ ステータスコードの確認
APIレスポンスを確認するときは、まずステータスコードを確認する。

代表的なステータスコード：
- 200 OK：リクエストが成功した
- 201 Created：データの作成に成功した
- 204 No Content：処理は成功したが、レスポンスボディはない
- 400 Bad Request：リクエストの内容に問題がある
- 401 Unauthorized：認証に問題がある
- 403 Forbidden：操作する権限がない
- 404 Not Found：指定したリソースが見つからない
- 500 Internal Server Error：サーバー内部でエラーが発生した

#### ④ レスポンスボディの確認
レスポンスボディには、APIの処理結果や取得したデータが含まれる。

JSON形式の場合は、キーと値の組み合わせでデータが表現される。

例えば、次のJSONではユーザーのID、名前、年齢を確認できる。

```json
{
  "id": 1,
  "name": "Taro",
  "age": 20
}
```
レスポンスボディを確認することで、必要なデータが正しく返されているか判断できる。

#### ⑤ エラー時のレスポンス確認
APIでエラーが発生した場合は、ステータスコードだけでなく、レスポンスボディに含まれるエラー情報も確認する。

例えば、次のようなエラーレスポンスがある。

```json
{
  "status": 400,
  "code": "INVALID_PARAMETER",
  "message": "入力内容が正しくありません"
}
```
エラーコードやメッセージを確認することで、何が原因で失敗したのかを把握しやすくなる。

#### ⑥ レスポンスを確認する理由
APIレスポンスを確認することで、次のことが分かる。
- リクエストが成功したか
- 必要なデータが返ってきているか
- データの形式が正しいか
- エラーが発生した場合、その原因は何か
APIを正しく利用するためには、リクエストを送るだけでなく、返ってきたレスポンスの内容まで確認することが重要。


### 7.6 FlutterアプリからAPIを利用する

#### ① FlutterアプリからAPIを利用するとは？

FlutterアプリからAPIを利用するとは、アプリからサーバーへHTTPリクエストを送信し、データを取得したり、登録・更新・削除などの処理を行ったりすること。

FlutterアプリはAPIを利用するクライアントとして動作する。

例えば、次のような機能でAPI通信が利用される。

- ユーザー情報の取得
- ログイン認証
- データの登録・更新
- 商品や記事の一覧取得
- データの削除

#### ② HTTP通信に利用するパッケージ

Flutterでは、HTTP通信を行うために専用のパッケージを利用できる。

代表的なパッケージ：

- **http**：HTTPリクエストを送信するためのシンプルなパッケージ
- **Dio**：インターセプターやタイムアウト設定など、より多くの機能を備えたHTTP通信パッケージ

これらを利用することで、Flutterアプリから簡単にAPI通信を行える。

#### ③ API通信の基本的な流れ

FlutterアプリからAPIを利用する場合、基本的には次の流れで処理する。

1. HTTPリクエストを送信する
2. サーバーからレスポンスを受け取る
3. ステータスコードを確認する
4. レスポンスボディからデータを取得する
5. JSONなどのデータをDartのオブジェクトに変換する
6. 取得したデータを画面に反映する

#### ④ FlutterでGETリクエストを送信する

`http` パッケージを利用すると、GETリクエストを送信できる。

例えば、ユーザー情報を取得する場合は次のように書く。

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<void> fetchUser() async {
  final response = await http.get(
    Uri.parse('https://api.example.com/users/1'),
  );

  if (response.statusCode == 200) {
    final data = jsonDecode(response.body);

    print(data['name']);
  } else {
    print('データの取得に失敗しました');
  }
}
```

このコードでは、次の処理を行っている。

- `http.get()`：GETリクエストを送信する
- `await`：通信処理が完了するまで待つ
- `response.statusCode`：ステータスコードを確認する
- `response.body`：レスポンスボディを取得する
- `jsonDecode()`：JSON文字列をDartで扱えるデータに変換する

#### ⑤ 非同期処理とエラーハンドリング

API通信には時間がかかる場合があるため、Flutterでは非同期処理を利用する。

主に次の仕組みを使う。

- **async**：非同期処理を行う関数を定義する
- **await**：非同期処理の完了を待つ
- **try-catch**：通信中に発生した例外を処理する

例えば、通信エラーに備える場合は次のように書く。

```dart
try {
  final response = await http.get(
    Uri.parse('https://api.example.com/users/1'),
  );

  if (response.statusCode == 200) {
    // 成功時の処理
  } else {
    // APIエラー時の処理
  }
} catch (e) {
  // 通信エラーなどの例外処理
}
```

ステータスコードによるエラーと、通信そのものに失敗した場合の例外は、分けて処理することが重要。

#### ⑥ API通信の結果を画面に反映する

API通信を行う画面では、通信状態に応じて表示を切り替える必要がある。

代表的な状態：

- **ローディング状態**：通信中であることを表示する
- **成功状態**：取得したデータを表示する
- **エラー状態**：エラーメッセージなどを表示する

例えば、通信中はインジケーターを表示し、通信が成功したら取得したデータを表示する。

Riverpodなどの状態管理ライブラリを利用すると、API通信の状態や取得したデータを管理しやすくなる。

#### ⑦ API通信で注意すること

FlutterアプリからAPIを利用するときは、次の点に注意する。

- 通信中のローディング表示を用意する
- 通信エラーやAPIエラーを適切に処理する
- タイムアウトを考慮する
- 不要なAPIリクエストを繰り返さない
- APIキーなどの秘密情報をアプリ内に直接埋め込まない
- 取得したデータが想定した形式か確認する

API通信では、データを取得するだけでなく、通信状態やエラーへの対応も重要になる。

### 7.7 第7章のまとめ

#### ① API仕様書とは？

API仕様書とは、APIの利用方法やルールをまとめたドキュメント。

主に次の情報が記載されている。

- エンドポイント（URL）
- HTTPメソッド
- リクエストパラメータ
- リクエストボディ
- レスポンスの形式
- ステータスコード
- 認証方法

APIを利用する側と開発する側が、共通のルールを確認するために使用する。

#### ② Swagger / OpenAPI

- **OpenAPI**：REST APIの仕様を記述するための標準的な形式
- **Swagger**：OpenAPIに関連するツール群
- **Swagger UI**：API仕様書をブラウザ上で表示し、リクエストを実行できるツール

APIの仕様確認や動作確認に利用される。

#### ③ Postmanとは？

Postmanとは、プログラムを書かずにAPIリクエストを送信し、レスポンスを確認できるツール。

主な機能：

- HTTPメソッドやURLの設定
- リクエストヘッダーの設定
- リクエストボディの設定
- APIリクエストの送信
- レスポンスの確認
- リクエストの保存や再利用

Swagger UIがAPI仕様の確認にも役立つのに対し、Postmanはリクエストの作成・実行・管理に便利。

#### ④ APIリクエストを実行する

APIリクエストとは、クライアントからサーバーへ送信する要求のこと。

主な構成要素：

- **HTTPメソッド**：どのような操作を行うか
- **URL**：どのリソースにアクセスするか
- **ヘッダー**：認証情報やデータ形式などの追加情報
- **リクエストボディ**：サーバーへ送信するデータ

代表的なヘッダー：

- `Content-Type`：送信するデータの形式
- `Authorization`：認証情報
- `Accept`：受け取りたいデータの形式

JSON形式のデータを送信する場合は、次のように指定する。

```http
Content-Type: application/json
```

#### ⑤ APIレスポンスを確認する

APIレスポンスとは、リクエストに対してサーバーが返す処理結果のこと。

主な構成要素：

- **ステータスコード**：処理結果
- **レスポンスヘッダー**：データ形式などの追加情報
- **レスポンスボディ**：返却されるデータやメッセージ

代表的なステータスコード：

- `200 OK`：成功
- `201 Created`：データ作成成功
- `204 No Content`：成功したがレスポンスボディはない
- `400 Bad Request`：リクエストに問題がある
- `401 Unauthorized`：認証に問題がある
- `403 Forbidden`：操作する権限がない
- `404 Not Found`：リソースが見つからない
- `500 Internal Server Error`：サーバー内部のエラー

レスポンスを確認するときは、ステータスコードだけでなく、レスポンスボディの内容も確認することが重要。

#### ⑥ FlutterアプリからAPIを利用する

FlutterアプリからAPIを利用するときは、HTTP通信パッケージを使用する。

代表的なパッケージ：

- `http`：シンプルなHTTP通信
- `Dio`：インターセプターやタイムアウト設定など、便利な機能を備えたHTTP通信

基本的な処理の流れ：

1. HTTPリクエストを送信する
2. レスポンスを受け取る
3. ステータスコードを確認する
4. レスポンスボディを取得する
5. JSONをDartのデータに変換する
6. 画面にデータを反映する

FlutterでAPI通信を行うときによく使う仕組み：

- `async`：非同期処理を行う関数を定義する
- `await`：非同期処理の完了を待つ
- `try-catch`：例外を処理する
- `jsonDecode()`：JSON文字列をDartで扱えるデータに変換する
- `jsonEncode()`：DartのデータをJSON文字列に変換する

また、通信中・成功・エラーの状態を管理し、画面に適切に反映することも重要。

そのうえで、FlutterアプリからHTTPリクエストを送信し、取得したデータをDartで扱える形式に変換して画面に反映する。
