# 2. HTTPリクエスト

## 2.1 HTTPリクエストとは

**HTTPリクエスト**とは、クライアントからサーバーへ送る要求のことです。

例えば、Webサイトを表示するときや、APIからデータを取得するとき、クライアントはサーバーに対してHTTPリクエストを送信します。

```text
クライアント
    │
    │ HTTPリクエスト
    ▼
サーバー
```

HTTPリクエストには、主に以下のような情報が含まれます。

* どのURLにアクセスするか
* どのような処理を要求するか
* 追加の情報を送るか
* サーバーへ送るデータがあるか

---

## 2.2 HTTPリクエストの構成

HTTPリクエストは、主に以下の要素で構成されます。

```text
HTTPメソッド
URL
ヘッダー
ボディ
```

例えば、以下のようなHTTPリクエストがあります。

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "name": "山田太郎",
    "age": 25
}
```

この例では、それぞれ以下の情報を表しています。

| 要素       | 内容                              |
| -------- | ------------------------------- |
| HTTPメソッド | `POST`                          |
| URL      | `/users`                        |
| ヘッダー     | `Host`、`Content-Type`           |
| ボディ      | `{ "name": "山田太郎", "age": 25 }` |

HTTPリクエストでは、これらの情報を組み合わせてサーバーへ要求を送ります。

---

## 2.3 HTTPメソッド

**HTTPメソッド**は、サーバーに対して「何をしたいのか」を指定するためのものです。

代表的なHTTPメソッドには以下があります。

| メソッド     | 主な用途        |
| -------- | ----------- |
| `GET`    | データを取得する    |
| `POST`   | データを登録する    |
| `PUT`    | データを更新する    |
| `PATCH`  | データの一部を更新する |
| `DELETE` | データを削除する    |

### GET

`GET`は、サーバーからデータを取得するときに使用します。

例えば、ユーザー一覧を取得する場合は以下のようになります。

```http
GET /users HTTP/1.1
Host: example.com
```

```text
「usersのデータを取得したい」
```

という要求をサーバーへ送っています。

---

### POST

`POST`は、サーバーへ新しいデータを登録するときなどに使用します。

例えば、新しいユーザーを登録する場合は以下のようになります。

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "name": "山田太郎",
    "age": 25
}
```

```text
「このユーザー情報を登録したい」
```

という要求をサーバーへ送っています。

---

### PUT

`PUT`は、既存のデータを更新するときに使用します。

例えば、ユーザーIDが1のユーザー情報を更新する場合は以下のようになります。

```http
PUT /users/1 HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "name": "山田太郎",
    "age": 26
}
```

---

### PATCH

`PATCH`もデータの更新に使用します。

`PUT`と比較すると、データの一部だけを更新するときによく使用されます。

例えば、年齢だけを更新する場合は以下のようになります。

```http
PATCH /users/1 HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "age": 26
}
```

---

### DELETE

`DELETE`は、データを削除するときに使用します。

例えば、ユーザーIDが1のユーザーを削除する場合は以下のようになります。

```http
DELETE /users/1 HTTP/1.1
Host: example.com
```

---

## 2.4 URL

HTTPリクエストでは、**URL**によってアクセスする対象を指定します。

例えば、以下のURLがあるとします。

```text
https://example.com/users/1
```

この場合、

```text
https://example.com
```

がサーバーのURLで、

```text
/users/1
```

がアクセスする対象を表します。

APIでは、URLによって操作するデータを指定することが多くあります。

例えば、

```text
GET /users
```

ならユーザー一覧、

```text
GET /users/1
```

ならIDが1のユーザー、

```text
GET /products
```

なら商品一覧を取得する、といった使い方ができます。

---

## 2.5 クエリパラメータ

URLには、**クエリパラメータ**と呼ばれる追加の情報を指定することもできます。

クエリパラメータは、URLの`?`以降に記述します。

例えば、ユーザーを名前で検索する場合、

```text
/users?name=山田
```

のように指定できます。

```http
GET /users?name=山田 HTTP/1.1
Host: example.com
```

この場合、

```text
name=山田
```

がクエリパラメータです。

複数のパラメータを指定する場合は、`&`でつなぎます。

```text
/users?name=山田&age=25
```

この例では、

| パラメータ  | 値    |
| ------ | ---- |
| `name` | `山田` |
| `age`  | `25` |

を指定しています。

クエリパラメータは、検索条件や取得するデータの絞り込みなどに使用されます。

---

## 2.6 ヘッダー

**HTTPヘッダー**は、HTTPリクエストに関する追加情報を指定するためのものです。

例えば、以下のようなヘッダーがあります。

```http
Content-Type: application/json
```

`Content-Type`は、リクエストのボディに含まれているデータの形式を指定します。

APIでは、JSON形式のデータを送る場合に、

```http
Content-Type: application/json
```

と指定することがあります。

その他にも、認証情報などをヘッダーに指定することがあります。

例えば、以下のような形式です。

```http
Authorization: Bearer XXXXX
```

このように、HTTPヘッダーにはリクエストに関するさまざまな情報を指定できます。

---

## 2.7 リクエストボディ

**リクエストボディ**は、クライアントからサーバーへ送信するデータを格納する部分です。

特に、`POST`、`PUT`、`PATCH`などでデータを登録・更新するときに使用します。

例えば、ユーザーを登録する場合は以下のようになります。

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "name": "山田太郎",
    "age": 25
}
```

この例では、

```json
{
    "name": "山田太郎",
    "age": 25
}
```

がリクエストボディです。

このデータをサーバーへ送信することで、新しいユーザーの情報を登録できます。

---

## 2.8 GETとPOSTの違い

`GET`と`POST`は、APIで特によく使用されるHTTPメソッドです。

大まかに考えると、

```text
GET
→ データを取得する

POST
→ データを送信して登録する
```

という違いがあります。

例えば、ユーザー一覧を取得する場合、

```http
GET /users
```

新しいユーザーを登録する場合、

```http
POST /users
```

を使用します。

また、`GET`ではURLのクエリパラメータなどを使って条件を指定することがあります。

```text
GET /users?name=山田
```

一方、`POST`ではリクエストボディにデータを入れて送信することがあります。

```http
POST /users

{
    "name": "山田太郎",
    "age": 25
}
```

ただし、実際のAPIでは仕様によって異なるため、**「GETなら必ずこう、POSTなら必ずこう」と決めつけず、APIの仕様を確認することが重要です。**

---

## 2.9 HTTPリクエストの例

ここまで説明した内容を組み合わせると、以下のようなHTTPリクエストになります。

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer XXXXX

{
    "name": "山田太郎",
    "age": 25
}
```

このリクエストを分解すると、以下のようになります。

| 要素   | 内容                                    |
| ---- | ------------------------------------- |
| メソッド | `POST`                                |
| URL  | `/users`                              |
| ヘッダー | `Host`、`Content-Type`、`Authorization` |
| ボディ  | ユーザー情報のJSON                           |

つまり、

```text
POST
  ↓
「ユーザーを登録したい」

/users
  ↓
「usersを対象にする」

Content-Type
  ↓
「送信するデータはJSON形式」

Authorization
  ↓
「認証情報を送信する」

リクエストボディ
  ↓
「登録するユーザー情報」
```

という意味になります。

---

## 2.10 まとめ

* HTTPリクエストは、クライアントからサーバーへ送る要求
* HTTPメソッドによって、取得・登録・更新・削除などの目的を指定する
* URLによってアクセスする対象を指定する
* クエリパラメータによって検索条件などの追加情報を指定できる
* HTTPヘッダーには、リクエストに関する追加情報を指定する
* リクエストボディには、サーバーへ送信するデータを格納する
* `GET`はデータ取得、`POST`はデータ登録などで使用される
* 実際のAPIでは、APIの仕様に従ってリクエストを作成することが重要

HTTPリクエストでは、**「何を」「どこに」「どのような情報と一緒に」送るのか**を指定しています。
