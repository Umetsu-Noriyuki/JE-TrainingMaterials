### 2.1 1xx・2xx・3xx・4xx・5xxのおさらい

HTTPステータスコードとは、サーバーがクライアントからの
リクエストを受け取ったあと、その処理結果や状況を伝えるための3桁の数字のこと。

#### HTTPステータスコードの5つの分類

| 分類 | 意味 | 内容 |
|---|---|---|
| 1xx | 情報 | リクエストの処理が継続中 |
| 2xx | 成功 | リクエストが正常に処理された |
| 3xx | リダイレクト | 追加の処理や別の場所への移動が必要 |
| 4xx | クライアントエラー | リクエストに問題がある |
| 5xx | サーバーエラー | サーバー側で問題が発生した |

#### 1xx：情報

| コード | 意味 |
|---|---|
| 100 Continue | リクエストの続行が可能 |

#### 2xx：成功

| コード | 意味 |
|---|---|
| 200 OK | 正常に処理された |
| 201 Created | 新しいリソースが作成された |
| 202 Accepted | リクエストを受け付けた |
| 204 No Content | 正常に処理されたが、返す内容がない |

#### 3xx：リダイレクト

| コード | 意味 |
|---|---|
| 301 Moved Permanently | リソースが恒久的に移動した |
| 302 Found | リソースが一時的に別の場所にある |
| 304 Not Modified | リソースが変更されていない |

#### 4xx：クライアントエラー

| コード | 意味 |
|---|---|
| 400 Bad Request | リクエストの内容が不正 |
| 401 Unauthorized | 認証が必要、または認証に失敗した |
| 403 Forbidden | アクセスする権限がない |
| 404 Not Found | 指定したリソースが見つからない |
| 409 Conflict | リソースの状態などと競合している |

#### 5xx：サーバーエラー

| コード | 意味 |
|---|---|
| 500 Internal Server Error | サーバー内部で予期しないエラーが発生 |
| 502 Bad Gateway | ゲートウェイやプロキシが不正な応答を受け取った |
| 503 Service Unavailable | サーバーが一時的に利用できない |
| 504 Gateway Timeout | ゲートウェイなどが応答を待ちきれずタイムアウトした |


## 2.2 3xx リダイレクト

### ① リダイレクトとは？

リダイレクトとは、クライアント（ブラウザやアプリ）に対して、別のURLへ移動するように伝える仕組みのこと。

例えば、WebサイトのURLが変更された場合、変更前のURLにアクセスすると、サーバーは新しいURLをクライアントに伝えることができる。

このときに使われるのが、3xx系のステータスコード。

### ② よく使われる3xx系ステータスコード

| ステータスコード | 意味 | 使用例 |
|---|---|---|
| 301 Moved Permanently | 恒久的な移転 | WebサイトのURLを正式に変更した |
| 302 Found | 一時的な移転 | 一時的に別のページへ移動させる |
| 304 Not Modified | 変更なし | 保存済みのデータをそのまま利用できる |

### ③ 301と302の違い

- 301 Moved Permanently：移動先が恒久的に変更されたことを表す。
- 302 Found：一時的に別のURLへ移動していることを表す。

### ④ 304 Not Modifiedとは？

304は、クライアントが持っているデータから変更がないことを表すステータスコード。

例えば、ブラウザが以前取得した画像を保存している場合、サーバーに変更があるか確認することがある。

変更されていなければ、サーバーは304を返し、ブラウザに保存済みの画像を使うように伝える。

これによって、不要なデータ通信を減らすことができる。


## 2.3 代表的なステータスコードの使い分け

### ① 200 OK

リクエストが正常に処理されたことを表す。

例：ユーザー情報を正常に取得できた場合。

### ② 201 Created

リクエストが成功し、新しいリソースが作成されたことを表す。

例：新しいユーザーを登録できた場合。

### ③ 204 No Content

リクエストは正常に処理されたが、レスポンスボディを返さない場合に使う。

例：ユーザー情報の削除が成功した場合。

### ④ 400 Bad Request

リクエストの内容に問題がある場合に使う。

例：必要なパラメータが不足している、入力形式が間違っている場合。

### ⑤ 401 Unauthorized

認証が必要なのに認証されていない、または認証情報が正しくない場合に使う。

例：ログインしていない状態でユーザー専用APIにアクセスした場合。

### ⑥ 403 Forbidden

認証はできているが、その操作を行う権限がない場合に使う。

例：一般ユーザーが管理者専用のAPIを利用しようとした場合。

### ⑦ 404 Not Found

指定したリソースが存在しない場合に使う。

例：存在しないユーザーIDを指定して取得しようとした場合。

### ⑧ 409 Conflict

現在のリソースの状態とリクエストが矛盾している場合に使う。

例：すでに登録されているメールアドレスを使って、新しいユーザーを登録しようとした場合。

### ⑨ 500 Internal Server Error

サーバー内部で予期しないエラーが発生した場合に使う。

例：プログラムの不具合などで正常に処理できなかった場合。


## 2.4 ステータスコードの設計

### ① ステータスコードを適切に使う理由

APIでは、リクエストの処理結果に応じて適切なステータスコードを返すことが大切。

クライアント側は、ステータスコードを確認して処理を切り替えることができる。

例：
- 200：取得成功なので、取得したデータを画面に表示する
- 201：登録成功なので、登録完了画面を表示する
- 400：入力内容に問題があるので、入力を修正してもらう
- 401：認証されていないので、ログイン画面へ移動する
- 500：サーバー側の問題なので、エラーメッセージを表示する

### ② HTTPメソッドとステータスコードの組み合わせ

| HTTPメソッド | 処理内容 | よく使われるステータスコード |
|---|---|---|
| GET | データ取得 | 200 OK |
| POST | データ新規作成 | 201 Created |
| PUT | データ全体の更新 | 200 OK / 204 No Content |
| PATCH | データの一部更新 | 200 OK / 204 No Content |
| DELETE | データ削除 | 204 No Content |

※実際にどのコードを返すかはAPIの仕様によって異なる。

### ③ エラーの種類に応じて使い分ける

| 状況 | ステータスコード |
|---|---|
| リクエストの形式が間違っている | 400 Bad Request |
| ログインしていない | 401 Unauthorized |
| 操作する権限がない | 403 Forbidden |
| 指定したデータが存在しない | 404 Not Found |
| データの状態が矛盾している | 409 Conflict |
| サーバー内部でエラーが発生した | 500 Internal Server Error |
| サービスが一時的に利用できない | 503 Service Unavailable |

### ④ ステータスコードだけに頼らない

APIでは、ステータスコードだけでなく、レスポンスボディにエラーの詳細を含めることも大切。

例：

```json
{
  "error": "validation_error",
  "message": "入力内容に誤りがあります。",
  "details": {
    "email": "メールアドレスの形式が正しくありません。"
  }
}


## 2.5 2章のまとめ

### ① ステータスコードとは？

HTTPステータスコードとは、サーバーがクライアントに対して、リクエストの処理結果を伝えるための3桁の数字のこと。

### ② ステータスコードの分類

| 分類 | 意味 | 代表的なコード |
|---|---|---|
| 1xx | 情報 | 100 Continue |
| 2xx | 成功 | 200、201、204 |
| 3xx | リダイレクト | 301、302、304 |
| 4xx | クライアント側のエラー | 400、401、403、404、409 |
| 5xx | サーバー側のエラー | 500、502、503、504 |

### ③ 特に覚えておきたいステータスコード

| コード | 意味 |
|---|---|
| 200 OK | リクエスト成功 |
| 201 Created | リソースの作成成功 |
| 204 No Content | 処理成功・レスポンスボディなし |
| 301 Moved Permanently | 恒久的なリダイレクト |
| 302 Found | 一時的なリダイレクト |
| 304 Not Modified | リソースに変更なし |
| 400 Bad Request | リクエストの内容に問題がある |
| 401 Unauthorized | 認証されていない |
| 403 Forbidden | 操作する権限がない |
| 404 Not Found | リソースが存在しない |
| 409 Conflict | リソースの状態とリクエストが矛盾している |
| 500 Internal Server Error | サーバー内部のエラー |
| 503 Service Unavailable | サービスを一時的に利用できない |

### ④ ステータスコードは適切に使い分ける

APIでは、処理結果やエラーの原因に応じて適切なステータスコードを返すことが大切。

また、ステータスコードだけでなく、レスポンスボディにエラーの詳細を含めることで、クライアント側が原因を把握しやすくなる。
