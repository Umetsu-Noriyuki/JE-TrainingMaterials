### 1.1 ログとは？

#### ① ログの基本的な意味

ログとは、アプリケーションやシステムで発生した出来事や処理の内容を記録したデータのこと。

例えば、次のような情報がログとして記録される。

- ユーザーがログインした
- データベースからデータを取得した
- API通信が成功した
- エラーが発生した
- データの保存に失敗した

ログを確認することで、システムがどのように動作したのか、どこで問題が発生したのかを把握できる。

#### ② ログを記録する目的

ログを記録する主な目的は、システムの動作状況を把握し、問題が発生した際に原因を調査できるようにすること。

主な目的は次のとおり。

| 目的 | 内容 |
|---|---|
| 動作確認 | システムが正常に動作しているか確認する |
| エラー調査 | エラーが発生した原因を特定する |
| 障害対応 | システム障害が発生した際の状況を把握する |
| 利用状況の確認 | ユーザーの操作やアクセス状況を確認する |
| システム改善 | 問題点や改善すべき箇所を見つける |

#### ③ ログ調査が重要な理由

アプリケーションでエラーが発生した場合、画面上には「データの取得に失敗しました」のような簡単なメッセージしか表示されないことがある。

しかし、実際には次のような原因が考えられる。

- APIとの通信に失敗した
- データベースに接続できなかった
- SQLの実行中にエラーが発生した
- 取得したデータの形式が想定と異なっていた
- プログラムの処理に不具合があった

このような場合、ログを確認することで、どの処理で問題が発生したのか、エラーの直前に何が起きていたのかを調べられる。

そのため、ログはシステム内部の動作を理解し、問題の原因を特定するための重要な手がかりとなる。


### 1.2 ログ調査とデバッグの違い

#### ① ログ調査とは？

ログ調査とは、アプリケーションやシステムが出力したログを確認し、動作状況やエラーの原因を調べること。

主に、実行済みの処理や過去に発生した問題を確認するときに利用する。

例えば、次のようなログが出力されていたとする。

```text
2026-11-04 10:00:00 INFO  APIリクエスト開始
2026-11-04 10:00:01 INFO  データベース接続開始
2026-11-04 10:00:02 ERROR データベース接続失敗
```

このログを確認することで、APIリクエストの途中でデータベース接続に失敗したことが分かる。

#### ② デバッグとは？

デバッグとは、プログラムの動作を確認しながら、バグ（不具合）の原因を特定・修正すること。

主に、プログラムの実行中に変数の値や処理の流れを確認するときに利用する。

代表的な方法には、次のようなものがある。

- ブレークポイント：指定した行でプログラムを一時停止する
- ステップ実行：1行ずつ処理を進める
- 変数の確認：実行中の変数の値を確認する

#### ③ ログ調査とデバッグの違い

| 比較項目 | ログ調査 | デバッグ |
|---|---|---|
| 主な目的 | 動作状況やエラー原因の確認 | バグの原因特定・修正 |
| 確認方法 | 出力済みのログを読む | プログラムを実行して内部を確認する |
| 主な利用場面 | 本番環境の障害調査など | 開発中の不具合調査など |
| 特徴 | 過去の処理も確認できる | 処理を止めて詳細に確認できる |

#### ④ 2つを組み合わせて調査する

ログ調査とデバッグは、どちらか一方だけを使うものではない。

例えば、アプリでエラーが発生した場合は、次のように進められる。

1. ログを確認して、エラーが発生した処理を特定する
2. エラーが発生した箇所のコードを確認する
3. デバッグで変数や処理の流れを調べる
4. 原因を特定して修正する

このように、ログ調査で問題の発生箇所を絞り込み、デバッグで詳しい原因を調べると効率的。

#### ⑤ この章のポイント

- ログ調査は、出力されたログからシステムの動作やエラー原因を調べること
- デバッグは、プログラムを実行しながら内部の状態を確認すること
- 2つを組み合わせることで、問題の原因を効率よく特定できる


### 1.3 ログを利用する場面

#### ① エラーや不具合が発生したとき

アプリケーションでエラーや不具合が発生した場合、ログを確認することで原因を調査できる。

例えば、次のような問題が発生したとする。

- APIからデータを取得できない
- データベースへの保存に失敗する
- 画面を開くとアプリがクラッシュする
- 想定していないデータが表示される

このような場合、エラーが発生した時刻や処理内容、エラーメッセージなどをログから確認する。

#### ② システム障害が発生したとき

本番環境でシステム障害が発生した場合、ログは原因や影響範囲を調査するために重要となる。

例えば、次のような状況が考えられる。

- サーバーに接続できなくなった
- APIのレスポンスが返ってこない
- データベースへの接続がタイムアウトする
- 多くのユーザーが同時にエラーになっている

障害発生時のログを確認することで、いつから問題が発生したのか、どの処理に影響が出ているのかを把握できる。

また、障害が解消した後にログを振り返ることで、再発防止にも役立てられる。

#### ③ ユーザーの操作や利用状況を確認するとき

ログには、ユーザーの操作やシステムへのアクセス状況が記録されることもある。

例えば、次のような情報を確認できる。

- ログインやログアウトの履歴
- 画面へのアクセス履歴
- APIへのリクエスト履歴
- 特定の機能が利用された回数

これらを分析することで、ユーザーがどの機能をよく利用しているのか、どの操作で問題が発生しやすいのかを把握できる。

#### ④ システムの性能を確認するとき

ログには、処理にかかった時間やAPIの応答時間などを記録することもできる。

例えば、次のような情報を確認する。

- APIのレスポンスにかかった時間
- データベースの検索にかかった時間
- 処理が完了するまでの時間
- タイムアウトが発生した回数

これらを確認することで、処理が遅くなっている箇所を特定し、システムの性能改善につなげられる。

#### ⑤ セキュリティ上の問題を調査するとき

ログは、不正アクセスや不審な操作など、セキュリティ上の問題を調査するときにも利用される。

例えば、次のような情報を確認する。

- ログイン失敗の履歴
- 通常とは異なるアクセス
- 権限のない操作の試行
- アカウントや設定の変更履歴

これらのログを確認することで、不審な操作の発生状況を把握し、セキュリティ対策に役立てられる。

ただし、パスワードやアクセストークンなどの機密情報をログに出力してはいけない。

#### ⑥ この章のポイント

ログは、エラー調査だけでなく、障害対応や利用状況の確認、性能改善、セキュリティ対策など、さまざまな場面で利用される。

システムの状態を把握し、問題の早期発見や再発防止につなげるために重要な役割を持っている。


### 1.4 第1章まとめ

#### ① ログとは？

ログとは、アプリケーションやシステムで発生した出来事や処理の内容を記録したデータのこと。

システムの動作状況やエラーの発生状況を確認するために利用される。

#### ② ログ調査とデバッグの違い

| 項目 | ログ調査 | デバッグ |
|---|---|---|
| 目的 | 動作状況やエラー原因の確認 | バグの原因特定・修正 |
| 方法 | 出力されたログを確認する | プログラムを実行して内部を確認する |
| 主な用途 | 本番環境の障害調査など | 開発中の不具合調査など |

ログ調査で問題の発生箇所を絞り込み、デバッグで詳しい原因を調べることで、効率よく問題を解決できる。

#### ③ ログを利用する主な場面

ログは、次のような場面で利用される。

| 利用場面 | 確認する内容 |
|---|---|
| エラー・不具合調査 | エラーの発生時刻や原因 |
| システム障害対応 | 障害の発生状況や影響範囲 |
| 利用状況の確認 | ユーザーの操作やアクセス履歴 |
| 性能確認 | APIの応答時間や処理時間 |
| セキュリティ調査 | 不正アクセスや不審な操作 |

#### ④ 第1章の重要ポイント

- ログは、システム内部の動作や処理内容を記録したデータである
- ログを利用することで、エラーの原因や障害の発生状況を調査できる
- ログ調査は出力されたログを確認する方法、デバッグはプログラムの内部状態を確認する方法
- ログはエラー調査だけでなく、性能改善やセキュリティ対策にも利用される
- ログ調査とデバッグを組み合わせることで、問題の原因を効率よく特定できる
