### 3.1 ログ出力とは？

#### ① ログ出力とは？

ログ出力とは、アプリケーションやシステムで発生した処理内容やイベント、エラーなどを記録すること。

例えば、次のような情報をログとして出力する。

- ユーザーがログインした
- データベースからデータを取得した
- APIとの通信に成功した
- データの保存に失敗した
- 予期しないエラーが発生した

ログを出力しておくことで、後からシステムの動作を確認したり、問題が発生した原因を調査したりできる。

#### ② ログはどこに出力されるのか？

ログは、主に次のような場所に出力される。

| 出力先 | 内容 |
|---|---|
| コンソール | ターミナルや開発ツール上に表示される |
| ログファイル | ファイルとして保存される |
| ログ管理サービス | 外部サービスに送信して一元管理する |

例えば、Flutterアプリの開発中に `print()` を使うと、VS Codeのデバッグコンソールなどに文字列を表示できる。

一方、本番環境ではログファイルやログ管理サービスを利用して、ログを保存・検索できるようにすることが多い。

#### ③ 開発環境と本番環境のログ出力

ログの出力方法や設定は、開発環境と本番環境で異なることがある。

| 環境 | ログ出力の目的 |
|---|---|
| 開発環境 | 処理の確認やデバッグ |
| テスト環境 | テスト結果や不具合の確認 |
| 本番環境 | 障害調査やシステムの稼働状況の確認 |

例えば、開発環境では変数の値など細かい情報を出力することがあるが、本番環境では不要な情報や機密情報を出力しないようにする必要がある。

#### ④ ログ出力とログ調査の関係

ログ調査を行うためには、そもそも調査に必要な情報がログとして出力されていなければならない。

例えば、データ保存に失敗したときに、単に「エラーが発生しました」としか記録されていなければ、原因を特定するのは難しい。

そのため、ログを出力する段階で次のような情報を記録しておくことが重要。

- どの処理で発生したのか
- どのような操作を行ったのか
- どのようなエラーが発生したのか
- エラーの詳細情報は何か

**ログ調査のしやすさは、ログを出力する段階で大きく変わる。**


### 3.2 ログ出力の基本的な方法

#### ① print() によるログ出力

`print()` は、指定した文字列や値をコンソールに表示するための基本的な方法。

FlutterやDartでは、次のように使用できる。

```dart
void main() {
  print('アプリケーションを起動しました');
  print('ユーザー情報を取得しました');
}
```

実行すると、コンソールに次のように表示される。

```text
アプリケーションを起動しました
ユーザー情報を取得しました
```

`print()` は手軽に使えるため、開発中の簡単な動作確認などに利用される。

ただし、大規模なアプリケーションや本番環境でのログ管理には、ログレベルや出力先を管理できる仕組みを利用することが望ましい。

#### ② ログレベルを指定したログ出力

ログを出力するときは、重要度に応じてログレベルを使い分けることができる。

例えば、次のような出力方法がある。

```dart
import 'dart:developer' as developer;

void main() {
  developer.log(
    'ユーザー情報を取得しました',
    name: 'UserService',
    level: 800,
  );

  developer.log(
    'ユーザー情報の取得に失敗しました',
    name: 'UserService',
    level: 1000,
  );
}
```

Dartの `developer.log()` では、`level` に数値を指定してログの重要度を表現できる。

代表的な数値の例は次のとおり。

| 数値 | 意味 |
|---|---|
| 500 | DEBUG相当 |
| 800 | INFO相当 |
| 900 | WARNING相当 |
| 1000 | ERROR相当 |

※ 数値とログレベルの対応は利用するライブラリやログ管理の仕組みによって異なる場合がある。

#### ③ ログライブラリを利用する方法

実際のアプリケーション開発では、ログ出力を管理するために専用のライブラリを利用することもある。

ログライブラリを利用すると、次のような管理がしやすくなる。

- ログレベルの使い分け
- ログの出力形式の統一
- ログの出力先の管理
- 不要なログの出力制御
- エラー情報やスタックトレースの記録

例えば、Flutter・Dartでは `logger` などのパッケージが利用されることがある。

#### ④ エラー情報を含めたログ出力

エラーが発生した場合は、エラーメッセージだけでなく、例外情報やスタックトレースも記録すると原因を調査しやすくなる。

```dart
try {
  // データ取得処理
} catch (error, stackTrace) {
  developer.log(
    'データの取得に失敗しました',
    name: 'DataService',
    error: error,
    stackTrace: stackTrace,
    level: 1000,
  );
}
```

ここでは、次の情報を記録している。

| 項目 | 内容 |
|---|---|
| メッセージ | どの処理で問題が発生したか |
| error | 発生した例外の内容 |
| stackTrace | エラーが発生するまでの呼び出し経路 |
| level | ログの重要度 |

特にスタックトレースは、どの関数を通ってエラーが発生したのかを調べる手がかりになる。

#### ⑤ ログ出力方法の使い分け

ログ出力には複数の方法があり、用途に応じて使い分けることが重要。

| 方法 | 主な用途 |
|---|---|
| print() | 簡単な動作確認 |
| developer.log() | ログレベルや発生元を指定したログ出力 |
| ログライブラリ | アプリケーション全体のログ管理 |

開発中は簡単なログ出力でも十分な場合があるが、本番環境ではログの管理や検索、保存方法も考慮する必要がある。


### 3.3 ログ出力のタイミング

#### ① 処理の開始時

重要な処理を開始したタイミングでログを出力すると、どの処理が実行されたのかを確認できる。

例えば、次のような処理がある。

- ユーザー情報の取得を開始した
- データベースへの接続を開始した
- バックアップ処理を開始した
- APIへのリクエストを開始した

```dart
developer.log(
  'ユーザー情報の取得を開始します',
  name: 'UserService',
  level: 800,
);
```

処理開始時のログがあると、後から処理が実行されたかどうかを確認しやすくなる。

#### ② 処理の終了時

処理が正常に完了したタイミングでもログを出力する。

```dart
developer.log(
  'ユーザー情報の取得が完了しました',
  name: 'UserService',
  level: 800,
);
```

開始時と終了時のログを比較することで、処理が正常に完了したのか、途中で止まっているのかを判断しやすくなる。

また、開始時刻と終了時刻を記録すれば、処理にかかった時間も調査できる。

#### ③ エラーが発生した時

エラーや例外が発生したタイミングでは、原因を調査できるようにログを出力する。

```dart
try {
  await fetchUser();
} catch (error, stackTrace) {
  developer.log(
    'ユーザー情報の取得に失敗しました',
    name: 'UserService',
    error: error,
    stackTrace: stackTrace,
    level: 1000,
  );
}
```

エラー発生時には、次のような情報を記録すると調査しやすくなる。

- エラーが発生した処理
- エラーの内容
- 発生した日時
- スタックトレース

#### ④ 重要なデータを変更した時

データの登録・更新・削除など、重要な変更が行われたタイミングでもログを出力することがある。

例えば、

- ユーザー情報を登録した
- プレーヤー情報を更新した
- 試合記録を削除した
- アカウントの権限を変更した

こうした操作を記録することで、後から誰がどのような変更を行ったのかを確認しやすくなる。

このような記録は、監査ログとして管理されることもある。

#### ⑤ 外部サービスと通信した時

APIや外部サービスとの通信では、リクエストやレスポンスに関する情報を記録すると、通信トラブルの調査に役立つ。

例えば、

- APIへのリクエストを送信した
- APIからレスポンスを受信した
- HTTPステータスコードが500だった
- 通信がタイムアウトした

```dart
developer.log(
  'APIリクエストに失敗しました。statusCode: 500',
  name: 'ApiService',
  level: 1000,
);
```

ただし、認証トークンやパスワードなどの機密情報をログに出力してはいけない。

#### ⑥ 処理時間を計測する時

処理に時間がかかっていないかを確認したい場合は、処理の開始時刻と終了時刻を記録する。

例えば、次のように計測できる。

```dart
final stopwatch = Stopwatch()..start();

await fetchUser();

stopwatch.stop();

developer.log(
  'ユーザー情報の取得時間: ${stopwatch.elapsedMilliseconds}ms',
  name: 'UserService',
  level: 800,
);
```

この例では、処理にかかった時間をミリ秒単位で記録している。

処理時間を確認することで、API通信やデータベース処理など、時間がかかっている箇所を特定しやすくなる。

#### ⑦ ログ出力のタイミングを整理する

ログを出力する代表的なタイミングを整理すると、次のようになる。

| タイミング | 記録する目的 |
|---|---|
| 処理の開始時 | 処理が実行されたことを確認する |
| 処理の終了時 | 処理が正常に完了したことを確認する |
| エラー発生時 | エラーの内容や原因を調査する |
| データ変更時 | 重要な変更履歴を確認する |
| 外部通信時 | API通信などの状況を確認する |
| 処理時間の計測時 | パフォーマンスを確認する |

**ログは、後から処理の流れや問題の原因を追跡できるタイミングで出力することが重要。**


### 3.4 ログ出力時の注意点

#### ① 個人情報や機密情報を出力しない

ログには、ユーザーの情報やシステム内部の情報が含まれることがある。

しかし、次のような情報をそのままログに出力してはいけない。

- パスワード
- アクセストークン
- APIキー
- クレジットカード番号
- 個人を特定できる情報

これらがログに残ると、ログファイルやログ管理サービスから情報が漏洩する危険性がある。

例えば、次のようなログは危険。

```dart
print('ログイン情報: password=$password');
```

必要に応じて情報をマスキング（隠すこと）したり、そもそもログに出力しないようにしたりする。

#### ② 不要なログを大量に出力しない

ログを大量に出力すると、次のような問題が発生する。

- ログファイルの容量が増加する
- 必要なログを見つけにくくなる
- ログの保存や検索に時間がかかる
- システムの処理速度に影響する場合がある

そのため、ログは必要な情報に絞って出力することが重要。

特に、ループ処理などで大量のログが出力されないように注意する。

#### ③ 適切なログレベルを設定する

ログの内容に応じて、適切なログレベルを設定する。

| 状況 | ログレベルの例 |
|---|---|
| 正常に処理が完了した | INFO |
| 開発中の詳細な処理情報 | DEBUG |
| 注意が必要だが処理は継続できる | WARN |
| 処理に失敗した | ERROR |

すべてのログをERRORにしてしまうと、本当に重要なエラーを見つけにくくなる。

ログの重要度に合わせて使い分けることが大切。

#### ④ エラーの詳細情報を記録する

エラーが発生したときに、単に「エラーが発生しました」とだけ記録しても、原因を特定するのは難しい。

可能な範囲で、次のような情報を記録するとよい。

- エラーが発生した処理
- 例外の内容
- スタックトレース
- 発生した日時
- 関連する処理の情報

ただし、詳細情報に個人情報や認証情報が含まれないように注意する。

#### ⑤ ログの保存期間や管理方法を決める

ログを長期間保存し続けると、ストレージ容量を圧迫する可能性がある。

そのため、次のような管理が必要になる。

- ログの保存期間を決める
- 古いログを削除・アーカイブする
- ログファイルの容量を管理する
- 必要なログを適切に保護する

また、ログにはシステム内部の情報が含まれることもあるため、閲覧できるユーザーや権限を制限することも重要。

#### ⑥ ログ出力時の注意点を整理する

| 注意点 | 理由 |
|---|---|
| 機密情報を出力しない | 情報漏洩を防ぐ |
| 不要なログを大量に出力しない | 容量増加や調査効率の低下を防ぐ |
| 適切なログレベルを設定する | 重要なログを見つけやすくする |
| エラーの詳細情報を記録する | 原因を特定しやすくする |
| 保存期間や閲覧権限を管理する | 安全かつ効率的にログを管理する |

**ログは多ければよいわけではなく、安全性と調査のしやすさを考えて出力することが重要。**

### 3.5 第3章まとめ

#### ① ログ出力とは？

ログ出力とは、アプリケーションやシステムで発生した処理内容やイベント、エラーなどを記録すること。

ログを出力しておくことで、後からシステムの動作を確認したり、問題が発生した原因を調査したりできる。

ログの主な出力先には、次のようなものがある。

| 出力先 | 内容 |

| ログ管理サービス | 外部サービスに送信して一元管理する |

#### ③ ログ出力のタイミング

ログは、調査に必要な情報を確認できるタイミングで出力することが重要。

| タイミング | 記録する目的 |
|---|---|

特に、処理の開始時刻と終了時刻を記録すると、処理にかかった時間を確認できる。

特に、パスワード・アクセストークン・APIキーなどの機密情報は、そのままログに出力してはいけない。

#### ⑤ 第3章の重要ポイント

第3章で学んだ内容を整理すると、次のようになる。

1. ログ出力とは、システムの処理内容やエラーなどを記録すること
2. Dartではprint()やdeveloper.log()などを利用できる
3. エラー発生時には例外情報やスタックトレースを記録するとよい
4. 処理の開始・終了・エラー発生時など、適切なタイミングでログを出力する
5. ログには機密情報を含めず、必要な情報に絞って記録する

**ログ調査を効率的に行うためには、調査しやすいログを適切なタイミングで、安全に出力することが重要。**
