### 9.1 ログの読み取り演習

#### 問題1：ログの読み取り

次のログを確認してください。

```text
09:00:00 INFO BackupService バックアップ処理を開始
09:00:02 ERROR DatabaseService データベース接続に失敗
09:00:05 INFO DatabaseService 再接続に成功
09:00:08 INFO BackupService バックアップ処理が完了
```

このログから読み取れる内容として、正しいものはどれでしょうか？

1. バックアップ処理は失敗している
2. データベースのデータが削除されている
3. 一度データベース接続に失敗したが、再接続に成功し、バックアップ処理も完了している
4. バックアップ処理は開始されていない

**正解：③**

**解説：**

09:00:02にデータベース接続が失敗していますが、09:00:05には再接続に成功しています。

その後、09:00:08にバックアップ処理が完了しているため、最終的には正常終了したと判断できます。

ERRORログが出ていても、その後の処理によって復旧している場合があります。

ログを確認するときは、エラーが発生した時点だけでなく、その後のログも確認することが重要です。

### 9.2 APIエラーの原因特定演習

#### 問題2：APIエラーの調査

次のログを確認してください。

```text
10:00:00 INFO ApiServer Request received GET /api/users/10 Request ID req-105
10:00:01 INFO UserService Retrieving user data
10:00:02 ERROR UserRepository Database connection failed
10:00:03 ERROR ApiServer Request failed Status 500 Request ID req-105
```

このエラーの原因として、最も可能性が高いものはどれでしょうか？

1. GETメソッドの使用方法に問題がある
2. Flutter側の入力フォームに問題がある
3. バックエンドからデータベースへの接続に失敗している
4. Flutter側の画面表示に問題がある

**正解：③**

**解説：**

ログを時系列で確認すると、次の流れになっています。

1. APIリクエストを受信
2. UserServiceでユーザー情報の取得を開始
3. UserRepositoryでデータベース接続に失敗
4. APIがHTTP 500を返却

このことから、データベースへの接続処理に問題が発生し、それがAPIエラーにつながったと考えられます。

次に確認するべき内容は、データベースサーバーの稼働状況や接続先の設定などです。

### 9.3 外部サービス連携エラーの調査演習

#### 問題3：外部サービスの通信エラー

次のログを確認してください。

```text
11:00:00 INFO PaymentService 決済処理を開始
11:00:01 INFO PaymentService 決済APIへリクエストを送信
11:00:10 ERROR PaymentService Connection timeout
11:00:11 ERROR OrderService 決済処理に失敗
```

この場合、最初に確認するべき内容として最も適切なものはどれでしょうか？

1. 注文データをすべて削除する
2. 外部の決済サービスの稼働状況やネットワーク、タイムアウト設定を確認する
3. エラーログを削除する
4. Flutter側の画面デザインを変更する

**正解：②**

**解説：**

Connection timeoutは、一定時間内に通信が完了しなかったことを示しています。

そのため、次のような項目を確認します。

- 外部の決済サービスで障害が発生していないか
- ネットワークに問題がないか
- 接続先URLが正しいか
- タイムアウト時間の設定が適切か

なお、決済処理ではタイムアウトが発生しても、実際には決済が完了している可能性があります。

安易に再実行すると二重決済につながるため、決済サービス側の処理結果も確認する必要があります。

### 9.4 複数ログを使った原因特定演習

#### 問題4：複数ログの関連付け

次のログを確認してください。

```text
12:00:00 INFO ApiServer Request received Request ID req-201
12:00:01 INFO OrderService 注文処理を開始
12:00:02 INFO OrderRepository 注文データを登録
12:00:03 ERROR PaymentService 決済APIとの通信に失敗
12:00:04 ERROR OrderService 注文処理に失敗
12:00:05 ERROR ApiServer Status 500
```

このログから考えられる原因として、最も適切なものはどれでしょうか？

1. APIリクエストがサーバーに届いていない
2. 注文データの登録処理が開始されていない
3. 外部の決済APIとの通信に失敗している
4. Flutter側の注文画面が表示されていない

**正解：③**

**解説：**

ログを時系列で確認すると、次の流れになっています。

1. APIリクエストを受信
2. 注文処理を開始
3. 注文データをデータベースに登録
4. 決済APIとの通信に失敗
5. 注文処理が失敗
6. APIがHTTP 500を返却

注文データの登録までは成功していますが、その後の決済APIとの通信に失敗しています。

このことから、外部の決済サービスとの通信が原因である可能性が高いと判断できます。

複数のログを関連付けることで、処理全体のどこで問題が発生したのかを特定できます。

### 9.5 総合的な原因特定演習

#### 問題5：総合的な原因特定

ある注文APIでエラーが発生しました。

調査したところ、次のことが分かりました。

- APIリクエストは正常に受信されている
- 注文データはデータベースに登録されている
- 外部の決済サービスへリクエストを送信した後、タイムアウトが発生している
- 最終的にAPIはHTTP 500を返している

この場合の対応として、最も適切なものはどれでしょうか？

1. APIログを削除して、もう一度同じ処理を実行する
2. データベースの注文データをすべて削除する
3. 外部決済サービスとの通信状況と実際の決済状態を確認し、原因を特定して修正・検証する
4. HTTPステータスコード500を200に変更する

**正解：③**

**解説：**

今回のケースでは、APIの受信や注文データの登録までは正常に完了しています。

その後、外部決済サービスとの通信でタイムアウトが発生しているため、まずは決済サービスとの通信状況を確認する必要があります。

また、タイムアウトが発生していても、決済自体は完了している可能性があります。

そのため、実際の決済状態を確認してから再実行などの対応を判断します。

原因を特定した後は、修正を行い、正常系・異常系の両方で動作確認を実施することが重要です。

### 9.6 第9章まとめ

第9章では、これまで学んできたログ調査の知識を使って、実践的な問題に取り組みました。

今回の演習で重要だったポイントは次の5つです。

| ポイント | 内容 |
|---|---|
| ログの読み取り | ERRORが発生した後の処理も確認する |
| APIエラーの調査 | APIからバックエンド、DBまでの処理を追う |
| 外部サービスの調査 | 通信状況やタイムアウト、サービスの稼働状況を確認する |
| 複数ログの関連付け | Request IDやTrace IDを使って処理を追跡する |
| 根本原因の特定 | 表面的なエラーだけで判断せず、原因を特定して修正・検証する |

#### ログ調査の基本的な流れ

1. エラーが発生した状況を確認する
2. 該当するログを探す
3. 時系列で処理の流れを確認する
4. 関連するログを調べる
5. 原因を切り分ける
6. 根本原因を特定する
7. 修正して動作確認を行う

ログ調査では、ひとつのエラーメッセージだけで原因を決めつけないことが重要です。

複数のログを組み合わせ、処理全体の流れを追うことで、根本原因を特定しやすくなります。
