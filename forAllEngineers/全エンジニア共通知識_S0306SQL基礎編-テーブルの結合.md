## 6. テーブルの結合

### 6.1 JOINとは

**`JOIN`** は、複数のテーブルを結合してデータを取得するときに使用します。

データベースでは、情報を用途ごとに複数のテーブルへ分けて管理することがあります。

例えば、以下のテーブルがあるとします。

### usersテーブル

| id | name |
| -: | ---- |
|  1 | 山田太郎 |
|  2 | 佐藤花子 |
|  3 | 鈴木一郎 |

### ordersテーブル

| id | user_id | product_name |
| -: | ------: | ------------ |
|  1 |       1 | ノートPC        |
|  2 |       2 | マウス          |

`orders.user_id` と `users.id` を利用すると、注文情報とユーザー情報を組み合わせることができます。

このように、**複数のテーブルに分かれている情報を組み合わせて取得する**ときに`JOIN`を使用します。

---

### 6.2 INNER JOIN

`INNER JOIN`は、**結合条件に一致するデータだけを取得する**方法です。

例えば、ユーザーと注文情報を結合するとします。

```sql
SELECT
    users.name,
    orders.product_name
FROM users
INNER JOIN orders
    ON users.id = orders.user_id;
```

`ON`の後に指定した条件、

```text
users.id = orders.user_id
```

が一致するデータだけが取得されます。

結果は以下のようになります。

| name | product_name |
| ---- | ------------ |
| 山田太郎 | ノートPC        |
| 佐藤花子 | マウス          |

`users`テーブルには鈴木一郎さんのデータがありますが、`orders`テーブルには鈴木一郎さんの注文データがありません。

そのため、`INNER JOIN`では鈴木一郎さんは結果に含まれません。

このように、`INNER JOIN`は

> **「両方のテーブルに存在するデータだけを取得したい」**

場合に使用します。

---

### 6.3 LEFT JOIN

`LEFT JOIN`は、**左側のテーブルのデータをすべて残しながら、右側のテーブルを結合する**方法です。

`INNER JOIN`では、両方のテーブルに一致するデータだけが取得されます。

一方、`LEFT JOIN`では、右側のテーブルに一致するデータがなくても、**左側のテーブルのデータは取得されます**。

#### 動作例

例えば、次のようなテーブルがあるとします。

### employeesテーブル

| id | name | department_id |
| -: | ---- | ------------: |
|  1 | 山田   |            10 |
|  2 | 佐藤   |            20 |
|  3 | 鈴木   |            30 |
|  4 | 田中   |          NULL |

### departmentsテーブル

| id | department_name |
| -: | --------------- |
| 10 | 営業部             |
| 20 | 開発部             |
| 30 | 総務部             |

この2つのテーブルを`LEFT JOIN`します。

```sql
SELECT
    employees.name,
    departments.department_name
FROM employees
LEFT JOIN departments
    ON employees.department_id = departments.id;
```

結果は次のようになります。

| name | department_name |
| ---- | --------------- |
| 山田   | 営業部             |
| 佐藤   | 開発部             |
| 鈴木   | 総務部             |
| 田中   | NULL            |

田中さんは`department_id`が`NULL`なので、`departments`テーブルに一致するデータがありません。

それでも`LEFT JOIN`では、**左側の`employees`のデータは残ります**。

右側のテーブルに一致するデータがないため、`department_name`には`NULL`が入ります。

```text
employees                    departments
┌────────┬───────────────┐   ┌────┬──────────────┐
│ name   │ department_id │   │ id │ department   │
├────────┼───────────────┤   ├────┼──────────────┤
│ 山田   │ 10            │──→│ 10 │ 営業部       │
│ 佐藤   │ 20            │──→│ 20 │ 開発部       │
│ 鈴木   │ 30            │──→│ 30 │ 総務部       │
│ 田中   │ NULL          │   │    │              │
└────────┴───────────────┘   └────┴──────────────┘
                                  ↑
                              一致するデータなし

結果
┌────────┬──────────────┐
│ name   │ department   │
├────────┼──────────────┤
│ 山田   │ 営業部       │
│ 佐藤   │ 開発部       │
│ 鈴木   │ 総務部       │
│ 田中   │ NULL         │
└────────┴──────────────┘
```

このように、`LEFT JOIN`では

> **「左側のテーブルを基準にして、右側に一致するデータがあれば追加する」**

と考えると分かりやすいです。

#### INNER JOINとの違い

`INNER JOIN`では、右側のテーブルに一致するデータがない田中さんは結果に含まれません。

一方、`LEFT JOIN`では田中さんも結果に含まれます。

| JOINの種類      | 一致するデータ | 一致しないデータ     |
| ------------ | ------- | ------------ |
| `INNER JOIN` | 取得される   | 取得されない       |
| `LEFT JOIN`  | 取得される   | 左側のデータは取得される |

そのため、

> **「左側のテーブルのデータを全部残したい」**

という場合には、`LEFT JOIN`を使用します。

---

### 6.4 JOINの基本構文

`JOIN`の基本的な構文は以下のとおりです。

```sql
SELECT カラム
FROM テーブルA
JOIN テーブルB
    ON テーブルA.カラム = テーブルB.カラム;
```

`ON`の後に、テーブルを結合する条件を指定します。

例えば、

```sql
ON users.id = orders.user_id
```

とした場合、`users`テーブルの`id`と`orders`テーブルの`user_id`が一致するデータを結合します。

また、`JOIN`にはいくつかの種類があります。

今回扱ったものは以下の2つです。

* `INNER JOIN`：両方のテーブルに一致するデータを取得する
* `LEFT JOIN`：左側のテーブルのデータをすべて残す

---

### 6.5 まとめ

* `JOIN`は、複数のテーブルを結合するときに使用する
* `ON`で結合条件を指定する
* `INNER JOIN`は、結合条件に一致するデータを取得する
* `LEFT JOIN`は、左側のテーブルのデータをすべて残す
* `LEFT JOIN`では、右側に一致するデータがない場合、その部分は`NULL`になる
* 「すべてのユーザー」「すべての社員」など、**基準となるテーブルのデータをすべて取得したい場合は`LEFT JOIN`が便利**
