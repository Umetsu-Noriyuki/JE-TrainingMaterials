# 5. JSONとAPI通信

## 5.1 JSONとは

JSONとは、**JavaScript Object Notation**の略で、データをやり取りするための形式の一つです。

JSONは人間にも読みやすく、さまざまなプログラミング言語で扱いやすいため、API通信でよく利用されています。

例えば、ユーザー情報をJSONで表すと次のようになります。

```json
{
  "id": 123,
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

この例では、ユーザーの

* ID
* 名前
* メールアドレス

をJSON形式で表しています。

---

## 5.2 JSONの基本構造

JSONでは、データを**キーと値の組み合わせ**で表現します。

```json
{
  "name": "山田太郎",
  "age": 25
}
```

例えば、

```text
"name" → "山田太郎"
"age"  → 25
```

となります。

このようなデータの組み合わせを**キーと値のペア**と呼びます。

### JSONで使用できる主なデータ型

JSONでは、主に次のデータ型を扱います。

| データ型   | 例                  |
| ------ | ------------------ |
| 文字列    | `"山田太郎"`           |
| 数値     | `25`               |
| 真偽値    | `true` / `false`   |
| null   | `null`             |
| オブジェクト | `{ "name": "山田" }` |
| 配列     | `[ "東京", "大阪" ]`   |

---

## 5.3 JSONのオブジェクト

JSONでは、`{}`で囲まれたデータを**オブジェクト**として表します。

```json
{
  "id": 123,
  "name": "山田太郎",
  "age": 25
}
```

複数のデータをまとめて扱う場合によく使用します。

APIのレスポンスでは、次のようなオブジェクトがよく返されます。

```json
{
  "id": 123,
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

---

## 5.4 JSONの配列

JSONでは、`[]`を使って複数のデータを配列として表します。

例えば、複数のユーザーを表す場合は次のようになります。

```json
[
  {
    "id": 1,
    "name": "山田太郎"
  },
  {
    "id": 2,
    "name": "佐藤花子"
  },
  {
    "id": 3,
    "name": "鈴木一郎"
  }
]
```

APIで一覧データを取得するときなどに、配列がよく利用されます。

---

## 5.5 APIでJSONを利用する

APIでは、JSONを使ってデータを送受信することがよくあります。

例えば、ユーザーを登録するAPIを考えてみます。

クライアントから次のようなリクエストを送ります。

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json
```

リクエストボディには、登録するユーザー情報をJSONで指定します。

```json
{
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

サーバーが処理を行うと、レスポンスとして登録されたユーザー情報が返されます。

```http
HTTP/1.1 201 Created
Content-Type: application/json
```

```json
{
  "id": 123,
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

このように、APIでは**JSONを使ってデータをやり取りする**ことができます。

---

## 5.6 Content-Type

HTTP通信では、送受信するデータの形式をヘッダーで指定することがあります。

そのときに使用するのが`Content-Type`です。

JSONを送信する場合は、次のように指定します。

```http
Content-Type: application/json
```

これは、

> 「このデータはJSON形式です」

ということを表しています。

例えば、JSONをリクエストボディに含める場合は、

```http
POST /users HTTP/1.1
Content-Type: application/json
```

```json
{
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

という形になります。

レスポンスでも、

```http
Content-Type: application/json
```

と指定されていれば、レスポンスボディがJSON形式であることを示しています。

## 5.7 API通信の一連の流れ

ここまで学習した内容を使って、API通信の流れを確認してみましょう。

例えば、ユーザー情報を取得する場合を考えます。

### ① クライアントからリクエストを送る

```http
GET /users/123 HTTP/1.1
Host: example.com
Accept: application/json
```

「ユーザーIDが123のユーザー情報をください」という要求です。

### ② サーバーが処理する

サーバーはリクエストを受け取り、必要なデータを取得します。

### ③ サーバーからレスポンスが返る

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "id": 123,
  "name": "山田太郎",
  "email": "yamada@example.com"
}
```

### ④ クライアントがデータを利用する

クライアントはレスポンスとして受け取ったJSONを利用して、画面にユーザー情報を表示するなどの処理を行います。

全体の流れをまとめると、次のようになります。

```text
┌─────────────┐
│ クライアント │
└──────┬──────┘
       │
       │ HTTPリクエスト
       │ GET /users/123
       ↓
┌─────────────┐
│     API     │
└──────┬──────┘
       │
       ↓
┌─────────────┐
│  サーバー    │
└──────┬──────┘
       │
       │ HTTPレスポンス
       │ 200 OK
       │ JSON
       ↓
┌─────────────┐
│ クライアント │
└─────────────┘
```

## 5.8 API通信をまとめて考える

ここまで学習した内容を組み合わせると、API通信は次のように整理できます。

| 要素       | 役割                        |
| -------- | ------------------------- |
| HTTP     | クライアントとサーバーが通信するための仕組み    |
| API      | プログラム同士がやり取りするための窓口       |
| REST API | RESTの考え方に沿って設計されたHTTP API |
| URL      | 操作するリソースを指定する             |
| HTTPメソッド | 操作の種類を指定する                |
| ヘッダー     | 通信に関する追加情報を指定する           |
| ステータスコード | 処理結果を表す                   |
| JSON     | データを表現する形式                |

例えば、

```http
GET /users/123
```

というリクエストの場合、

```text
GET
 ↓
ユーザー情報を取得する

/users/123
 ↓
ユーザー123というリソースを指定する
```

そして、サーバーから、

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "id": 123,
  "name": "山田太郎"
}
```

というレスポンスが返ってきます。

この一連の流れを理解できれば、API通信の基本的な仕組みを理解したと言えます。

## 5.9 APIを利用するときに確認すること

実際にAPIを利用するときは、APIの仕様を確認する必要があります。

主に次のような情報を確認します。

* APIのURL
* HTTPメソッド
* 必要なパラメータ
* 必要なヘッダー
* リクエストボディの形式
* 認証が必要か
* レスポンスの形式
* ステータスコード
* エラー時のレスポンス

例えば、APIの仕様書に次のような記載があったとします。

```text
GET /users/{id}

必要なパラメータ：
id

レスポンス：
JSON

成功時：
200 OK
```

この場合、

```http
GET /users/123
```

というリクエストを送ることで、ユーザーID「123」の情報を取得できます。

実際の開発では、APIの仕様書を確認しながらリクエストを組み立てることが重要です。

## 5.10 5章のまとめ

この章では、JSONとAPI通信について学びました。

重要なポイントは次のとおりです。

* **JSON**はデータを表現する形式の一つ

* `{}`はオブジェクト、`[]`は配列を表す
* APIではJSONがデータの送受信によく利用される
* `Content-Type: application/json`はJSON形式であることを示す
* API通信は「リクエスト → サーバーで処理 → レスポンス」という流れで行われる
* APIを利用するときは、URL・HTTPメソッド・パラメータ・ヘッダー・レスポンスなどの仕様を確認する
