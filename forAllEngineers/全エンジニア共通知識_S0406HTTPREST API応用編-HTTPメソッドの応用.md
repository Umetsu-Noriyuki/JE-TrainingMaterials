### 1.1 GET・POST・PUT・PATCH・DELETEのおさらい

HTTPメソッドとは、クライアントがサーバーに対して、
どのような処理を行いたいかを伝えるためのもの。

| メソッド | 役割 |
|---|---|
| GET | データを取得する |
| POST | データを新しく作成する |
| PUT | データを更新・置き換える |
| PATCH | データの一部を更新する |
| DELETE | データを削除する |

#### 具体例

| やりたいこと | HTTPメソッド |
|---|---|
| ユーザー一覧を取得する | GET |
| 新しいユーザーを登録する | POST |
| ユーザー情報をすべて更新する | PUT |
| ユーザーの名前だけ変更する | PATCH |
| ユーザーを削除する | DELETE |

### 1.2 PUTとPATCHの違い

PUTとPATCHは、どちらもサーバー上のデータを更新するときに使用するHTTPメソッド。

ただし、更新する範囲が異なる。

#### PUT
- 対象となるリソース全体を置き換えるためのメソッド
- 基本的に更新後のデータ全体を送信する

#### PATCH
- 対象となるリソースの一部分を変更するためのメソッド
- 変更したい部分のデータを送信する

#### PUTとPATCHの比較

| 比較項目 | PUT | PATCH |
|---|---|---|
| 更新範囲 | リソース全体 | リソースの一部分 |
| 送信データ | 基本的に全体 | 変更する部分 |
| 主な用途 | データの置き換え | 部分的な変更 |

### 1.3 冪等性（べきとうせい）とは

冪等性とは、同じ操作を何回繰り返しても、
1回だけ実行した場合と結果が変わらない性質のこと。

#### 冪等性があるHTTPメソッド

| メソッド | 冪等性 | 理由 |
|---|---|---|
| GET | あり | データを取得するだけ |
| PUT | あり | 同じ内容で置き換えても結果は同じ |
| DELETE | あり | 削除済みのデータを再度削除しても状態は同じ |

#### 冪等性がないことが多いHTTPメソッド

| メソッド | 冪等性 | 理由 |
|---|---|---|
| POST | 原則なし | 実行するたびに新しいデータが作られる場合がある |
| PATCH | 原則なし | 更新内容によって異なる |

※POSTやPATCHも、APIの設計によって冪等にすることができる。

#### なぜ冪等性が重要なのか

API通信では、通信エラーやタイムアウトが発生することがある。

同じリクエストを再送信した場合に、
データが重複して登録されたり、意図しない変更が発生したりする可能性がある。

そのため、冪等性を意識したAPI設計が重要になる。

### 1.4 安全なメソッドとは

安全なメソッド（Safe Method）とは、
サーバー上のデータを変更することを目的としないHTTPメソッドのこと。

#### 安全なメソッドの種類

| メソッド | 役割 |
|---|---|
| GET | データを取得する |
| HEAD | ヘッダー情報を取得する |
| OPTIONS | 通信で利用できるメソッドなどを確認する |

※TRACEもHTTP仕様上は安全なメソッド。

#### GETとHEADの違い

- GET：レスポンスヘッダーとボディの両方を受け取る
- HEAD：レスポンスヘッダーを受け取り、ボディは受け取らない

#### 安全性と冪等性の違い

| 用語 | 意味 |
|---|---|
| 安全性 | サーバー上のデータを変更することを目的としない |
| 冪等性 | 同じ操作を繰り返しても、最終的な結果が変わらない |

PUTは安全性がないが、冪等性はある。
DELETEも安全性がないが、冪等性はある。

### 1.5 HTTPメソッドの使い分け

HTTPメソッドは、それぞれ役割が決まっている。

APIを利用するときは、どのような処理を行いたいのかに合わせて、
適切なHTTPメソッドを選ぶことが重要。

#### URLとHTTPメソッドの組み合わせ

REST APIでは、URLで操作対象のリソースを指定し、
HTTPメソッドで実行したい処理を指定する。

- URL：どのデータを操作するか
- HTTPメソッド：どのような操作をするか

| HTTPメソッド | URL | 処理 |
|---|---|---|
| GET | /users | ユーザー一覧を取得 |
| GET | /users/1 | IDが1のユーザーを取得 |
| POST | /users | 新しいユーザーを登録 |
| PUT | /users/1 | ユーザー情報を置き換える |
| PATCH | /users/1 | ユーザー情報の一部を変更 |
| DELETE | /users/1 | ユーザーを削除 |

#### HTTPメソッドの特徴

| メソッド | 主な役割 | 安全性 | 冪等性 |
|---|---|---|---|
| GET | データ取得 | あり | あり |
| POST | データ作成など | なし | 原則なし |
| PUT | データの置き換え | なし | あり |
| PATCH | データの部分更新 | なし | 原則なし |
| DELETE | データ削除 | なし | あり |
| HEAD | ヘッダー取得 | あり | あり |
| OPTIONS | 通信方法の確認 | あり | あり |

※POSTやPATCHも、APIの設計によって冪等にできる場合がある。

#### PUTとPATCHの違い

- PUT：リソース全体を置き換える

- GET・PUT・DELETEは冪等性がある

サーバー上のデータを変更することを目的としないHTTPメソッドのこと。

GET・HEAD・OPTIONSなどが該当する。

#### 安全性と冪等性の違い

- 安全性：データの変更を目的としない
- 冪等性：同じ操作を繰り返しても最終的な結果が変わらない
